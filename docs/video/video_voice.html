Context as-experienced: assertions

Event stream as-observed

Events: one timestamp, record time = event time (R1: Slack ts, email Date:).
States: a window [valid_from, valid_to);
valid_to = null means “still believed true”.
assertion timelines from the graph
in scope at t ⇔ valid_from ≤ t < coalesce(valid_to, ∞)  ·  known at k ⇔ recorded_at ≤ k, not retracted (R10)
Elisa's model: the network in time-aware layers. Events have one timestamp; everything else is a state with a validity window.
A successor's valid_from closes its predecessor (R4b). Doubt changes status, never validity (R5). Stated dates mean 00:00 Helsinki.
So one query answers “what was true at time t?” and, with known_at, “what did we believe at that moment?”

kaiku seed loads the network layers from mock_data into Neo4j, every node and edge with its validity window.
Every write is UNWIND + MERGE on a stable key, so re-running changes nothing. Here is TRN-042's neighbourhood.
Assertions bind with a scope: observed_on the device, applies_to its model, activity for the topic. History is edges.
Then 12 temporal invariants run as Cypher; any violation fails the seed. Assertion text is embedded for semantic search.

Before recommending anything, the agent checks the assertion's symptoms against real telemetry.
Only complete 15-minute intervals count: at 06:21:30 that is 06:00–06:15. UP, RX −3.3 dBm, no traffic for an hour: all met.
After the bounce at 06:23 traffic recovers, and the same check says not_met. With no data it says unknown.

Agents can add evidence, never rewrite truth

report_outcome

resolved → SUPPORTS, support_n + 1
not_resolved + conditions met → REFUTES, refute_n + 1, review_due
not_resolved + conditions not met → not counted (the rule didn't apply)
not_resolved + conditions unknown → not counted, review_due
conditions are re-checked against telemetry at observed_at

three more writes

open_knowledge_gap → KnowledgeGap, routed to the top author
propose_assertion → status unverified, must cite ≥ 1 existing event
flag_assertion → sets review_due for a person
absent on purpose: confirm · retract · delete · edit validity
those stay with people
every write: agent_id from the bearer token (constant-time compare) · never from the request
idempotency_key → (:WriteReceipt {agent, tool, key}): a replay returns the first result
one transaction per write · recorded as an AgentAction event (R1: every write is itself an event)
Agents write back only evidence: outcomes, knowledge gaps, proposals and flags.
A failed fix counts against a rule only if its conditions were met, so wrong usage can't erode good knowledge.
Every write is attributed to the agent's token, idempotent, transactional, and itself an event.
